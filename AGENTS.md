# Repository guidance for coding agents

- Architecture: `src/extension/` contains the Manifest V3 dashboard, service worker, content relay, and page-world bridge. `src/chatgpt/` contains the provider adapter and validation. `src/core/` contains local storage, hashing, and archive logic. `public/manifest.json` limits extension hosts to `https://chatgpt.com/*`.
- Security boundary: authentication stays in the ChatGPT page world. Never persist or log tokens, cookies, signed asset URLs, account IDs, conversation data, or browser state. Asset downloads use the existing domain allowlist and redirect checks. Do not add telemetry, analytics, remote logging, or a backend.
- Compatibility entry points: `src/chatgpt/endpoints.ts` resolves allowlisted requests; `inventory.ts` handles Project cursors; `paginated-detail.ts` handles current conversation pages and backward pagination; `capture.ts` selects current or legacy detail retrieval.
- Preserve fail-closed behavior: initial conversation pages require at least one matching recognized identity; older message pages may omit identity, but every identity present must match. Preserve cursor-cycle, progress, byte/page-limit, archive-hash, resume, and reconciliation checks. Diagnostics must not echo raw IDs or content.
- Update private API adapters only from sanitized shape observations. Add synthetic fixtures and focused tests; never commit live responses or archive files. Run `npm run check`, `npm run test:e2e`, and `git diff --check` before proposing changes. Review `git status` and `npm run privacy:check` before any public push.
